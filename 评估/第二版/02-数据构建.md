# 02 · Phase 2A 路由数据构建

[评估索引](README.md) · [上一章](01-问题与基线.md) · [下一章](03-路由微调.md)

## 任务与标注规则

沿用三月的 **Phase 2A：单轮工具路由对齐**。三月原始训练集未留在本地，第二版重新生成数据；监督目标仍是一行路由 JSON，最终自然语言回答不参与这一阶段的训练。

| 决策 | 标注规则 | 输出字段 |
|---|---|---|
| `tool_call` | 需要查当前仓库，或需要处理已给出的代码、日志、生成需求 | `tool_name`、`arguments`；`clarify_answer=null` |
| `no_tool` | 通用概念、框架用法等，无需执行工具 | 工具、参数、追问及 `oracle_context` 均为 `null` |
| `clarify_needed` | 缺少关键信息，无法确定动作 | `clarify_answer` 为简短追问，其余分支字段为 `null` |

私域背景使用内部项目 **ModelHub-Serve（FastAPI + Transformers）**。问“本项目接口在哪里”应查库；问“FastAPI 通常怎样注册路由”应直接回答。检索意图明确时先查库，题目已给代码时优先分析代码，不能仅因提到框架名就检索。

规则实现在[生成背景](../../experiments/routing_data/project_context.py)、[生成器](../../experiments/routing_data/generate_data.py)和[清洗器](../../experiments/routing_data/clean_data.py)中。通识切片调用 `search_codebase` 会被标为 `far_general_search` 错误。

## 数据构建流程

| 阶段 | 处理 | 留存数据 |
|---|---|---|
| 生成 | 先试产 100 条，再生成 450 条；从后者分层留出 50 条测试 | [100 条](../../experiments/routing_data/outputs/ft_qa_100.jsonl)、[400 条训练](../../experiments/routing_data/outputs/ft_qa_450_train.jsonl)、[50 条测试](../../experiments/routing_data/outputs/ft_qa_450_test.jsonl) |
| 合并、检查 | 合并 400 + 100 条，处理 ID 冲突并检查字段、标签、参数 | [500 条候选](../../experiments/routing_data/outputs/ft_qa_500_train.jsonl) |
| 人工修订 | 7 条改为查库、1 条改为分析代码、1 条改为不调用；删除 3 条重复问题 | [497 条 v1](../../experiments/routing_data/outputs/ft_qa_500_train.reviewed.jsonl) |
| 补题 | 100 条隐式查库题 + 40 条容易被项目术语误导的通用概念题 | [隐式查库](../../experiments/routing_data/outputs/ft_qa_100_implicit_search.jsonl)、[概念直答](../../experiments/routing_data/outputs/ft_qa_40_concept_no_tool.jsonl) |
| v2 | 按 v1 → 隐式查库 → 概念直答的顺序合并，训练输入加入仓库简介 | [637 条 v2](../../experiments/routing_data/outputs/ft_qa_train_v2.jsonl) |

人工改动按历史 sample_id 记录在 [apply_review.py](../../experiments/routing_data/apply_review.py)，不能直接套到另一批随机生成的数据。

## 数据检查结果

| 数据 | 总数 | `tool_call` | `no_tool` | `clarify_needed` | ERROR / WARN / REVIEW |
|---|---:|---:|---:|---:|---|
| v1 | 497 | 303 | 96 | 98 | 0 / 0 / 35 |
| 隐式查库补题 | 100 | 100 | 0 | 0 | 0 / 0 / 0 |
| 概念直答补题 | 40 | 0 | 40 | 0 | 0 / 0 / 9 |
| v2 | 637 | 403 | 136 | 98 | 0 / 0 / 44 |

v2 内部没有完全重复的问题。44 个 `REVIEW` 是规则要求人工判断的标记，不是已确认的 44 条错误，也没有全部清零；人工修订保留了 v1 的其余 35 项。表中条数及审计数可由留存 JSONL 和清洗器的 `collect_issues()` 重算。

## 训练格式与测试集

ShareGPT 使用 `conversations`，每条消息为 `from/value`，角色是 `system/user/assistant`；assistant 金标包含 `decision_type`、`tool_name`、`arguments`、`clarify_answer`、`oracle_context`。LLaMA-Factory 必须使用 [dataset_info.json](../../lora/dataset_info.json) 的角色映射。转换逻辑见 [format_to_sharegpt.py](../../lora/format_to_sharegpt.py)。

| 文件 | 条数 | 用途 |
|---|---:|---|
| [routing_train_v1_no_summary.json](../../lora/routing_train_v1_no_summary.json) | 497 | v1，无仓库简介 |
| [routing_train.json](../../lora/routing_train.json) | 637 | v2，含 ModelHub-Serve 简介 |
| [eval_in_domain.json](../../lora/eval_in_domain.json) | 50 | 同分布测试；[无简介版本](../../lora/eval_in_domain_no_summary.json)用于条件对照 |
| [eval_cross_repo.json](../../lora/eval_cross_repo.json) | 87 | RepoAgent 人工题；[无简介版本](../../lora/eval_cross_repo_no_summary.json)用于条件对照 |
| [nanochat 冻结题目](../../data/v2/newrepo_nanochat60/questions_frozen.jsonl) | 60 | 后续新仓库路由测试，见第 03 章 |

50 条测试与 v1/v2 训练集有 **1 道问题及监督答案完全重合**：训练第 56 条、测试第 40 条；因此不能把同分布高分当作严格独立测试成绩。87 题没有发现这种完全重合，但已用于分析错例和确定补题方向，属于迭代验证集。

## 结论与复现

第二版数据的主要变化是补齐“隐式查库”和“术语概念直答”的边界。数据质量检查与实际路由效果分开验证，训练结果见[第 03 章](03-路由微调.md)。

在项目根目录执行以下离线命令，可按原顺序重建并核对 497/637 条训练数据、50 条测试，复制 87 条历史测试快照；全部一致后才写入独立目录，已有输出会拒绝覆盖：

```text
python -m experiments.routing_data.reproduce_data
```
