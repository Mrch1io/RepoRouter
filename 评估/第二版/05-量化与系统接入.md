# Q4 量化与系统接入评测

记录 Qwen3.5-4B LoRA v2 的 Q4_K_M 部署、早期三轮运行，以及两批完整回答对照。

[返回目录](README.md) · [上一章：检索与软熔断](04-检索与软熔断.md) · [下一章：回答质量与复盘](06-回答质量与复盘.md)

## 1. 实验设置

- **原生链路（Native）**：DeepSeek Flash 自己决定是否调用工具，再生成回答。
- **Q4 链路**：量化后的 4B v2 输出 `tool_call / no_tool / clarify_needed`；需要工具时先执行，再交给 Flash 回答。回答阶段不提供工具列表，澄清分支直接返回追问。
- 独立路由用 87 题，衡量三类决策；端到端用 90 题，按 legacy 标注衡量是否查库：35 道应检索、52 道不检索、3 道可选。两种准确率不能直接横比。
- 端到端对照均关闭软熔断。完整 90 题批次固定 原生链路 → Q4 链路 顺序，逐题配对；相邻时段运行仍受 API 负载、缓存和采样影响。

## 2. 量化与部署结果

| 项目 | 留存结果 |
|---|---:|
| 量化格式 | Q4_K_M |
| 独立路由 JSON 可解析 | 87/87 |
| 独立路由决策一致 | 82/87（94.3%） |
| 金标工具题中的工具名一致 | 32/35（91.4%） |
| 工具名＋arguments 严格全等 | 0/35 |
| 模型文件 | 2,708,804,192 字节，约 2.52 GiB |
| RTX 5090、8192 上下文，加载后整卡显存快照 | 3,535 MiB |
| 22 题试评的服务端平均路由计算耗时 | 243.3 毫秒 |

82/87 与未量化 v2 的本批成绩相同，仅说明这批路由决策成绩保留；严格参数全等不是语义质量评估。显存是加载后快照，不是峰值或最低需求；243.3 毫秒排除了预热，不含 SSH 往返、检索和 Flash 回答。

证据：[87 题量化路由日志](../../data/v2/logs/v2/route_ood_gguf_Q4_K_M.log) · [22 题服务配置与耗时](../../data/v2/pilot_full_answers/run.json)。

## 3. 早期端到端三轮运行

每组均为 **90 题 × 3 次**。此批 Q4 的 270 条最终评分仍为 `pending`，下表只比较查库决策、耗时和回答侧 API 费用。

| 链路 | 查库决策一致 | 平均耗时/题 | API 估算费用/题 |
|---|---:|---:|---:|
| Q4 路由＋Flash | 260/270（96.3%） | 3.470 秒 | $0.0007910 |
| Flash 原生，首轮 | 260/270（96.3%） | 4.870 秒 | $0.0011315 |
| Flash 原生，复跑 | 262/270（97.0%） | 4.231 秒 | $0.0011244 |
| Pro 原生 | 260/270（96.3%） | 10.659 秒 | $0.0036140 |

Q4 三轮决策分别正确 86、87、87 题；35 道应检索题重复三次，共实际检索 96/105，漏检 9 次，另有误检 1 次。270 次是重复观测，不是 270 道独立题。

## 5. 结论与费用口径

1. 4B v2 已完成量化和完整 Agent 接入。两批 90 题均观察到更低的运行耗时与 API 开销，但回答更短、调用更少也同时发生；不能把全部节省归于小模型计算提速。
2. 费用按冻结价格表估算**全部 DeepSeek 调用**，不含嵌入、评委、GPU 租金、电力与部署维护。
