## 实验设置

| 项目 | 设置 |
|---|---|
| 任务 | 沿用三月的 Phase 2A，预测 `tool_call` / `no_tool` / `clarify_needed`，以及工具和参数 |
| 基座 | Qwen3.5-4B；Qwen3.5-9B 只作原版基线，未完成 9B LoRA |
| 数据 | v1：497 条、无训练简介；补题消融：637 条、无训练简介；v2：637 条、有训练简介 |
| LoRA | rank 16、alpha 32、dropout 0.05，覆盖线性层，冻结视觉编码器 |
| 训练 | BF16，batch 2 × 梯度累积 4，学习率 1e-4，cosine，3 epochs，最大长度 2048 |
| 模板 | `qwen3_5_nothink`；推理关闭 thinking，本地 `do_sample=False` |
| 主要指标 | `decision_type` 一致率；另报该调用时调用、不该调用时未调用，以及参数合法性 |

配置见 [train_qwen35_4b.yaml](../../lora/autodl/train_qwen35_4b.yaml)。v1/v2 原运行分别为 189/240 步、约 36.3/47.6 分钟；可训练参数 32,464,896，约占 0.71%，训练仍需加载基座。训练成本与后续 GPU 部署成本不能用回答侧 API 费用替代。

## 补题、简介与训练步数消融

先完成 seed 42 的消融，再补 seed 43、44；下表采用后续统一复跑结果。无简介消融保留 v2 的 637 条样本、顺序和监督，只删除训练 system 的仓库简介。每个条件在同一批 87 题上评测。

| 训练条件 | 步数 | 推理简介 | 正确数：seed 42 / 43 / 44 | 平均一致率 |
|---|---:|---|---|---:|
| v1，497 条 | 189 | 无 | 71 / 73 / 69 | 81.6% |
| v1，只增加训练步数 | 240 | 无 | 74 / — / — | — |
| 补题，637 条、无训练简介 | 240 | 无 | 78 / 83 / 81 | 92.7% |
| v2，637 条、有训练简介 | 240 | 无 | 81 / 79 / 80 | 92.0% |
| 同一 v2 | 240 | 有 | 82 / 83 / 83 | 95.0% |

三次平均看，补题组比 v1 多对约 **9.7 题**；训练时加入简介没有进一步提高均值，推理时提供简介则每个 seed 多对 **1–4 题**。仅延长 v1 到 240 步多对 3 题，但只做了一个 seed，不能据此精确拆分数据内容和训练步数的贡献。50 题各条件、各 seed 均为 48–50 题正确。

首次单个随机种子 得到的“补题 +7、训练简介 +3、推理简介 +1”只是该次观察，后续三个随机种子 不支持把它写成固定贡献比例。2048-token 上限下，有训练简介 v2 截断 2 条输入，无简介版本截断同一条输入，监督答案完整；简介对照仍包含窗口占用差异。

证据：[首次消融](../../data/v2/ablation_v2_no_summary/results.json) · [三个随机种子 与步数对照](../../data/v2/seed_step/results.json) · [运行配置与输入](../../data/v2/seed_step/run.json)

## 新仓库 nanochat：60 题验证

对 nanochat 的固定版本 `92d63d4` 编写并冻结 60 道题：25 道应查代码（直接查库 15、隐式查库 10），35 道不应查库；包含 4 组同话题配对题。训练数据未包含该仓库，每个条件对冻结题集运行一次。三次 LoRA 结果仍按 seed 42 / 43 / 44 排列。

| 模型 | 无推理简介，正确数 /60 | 有推理简介，正确数 /60 |
|---|---|---|
| 4B 原版 | 39 | 48 |
| 9B 原版 | 51 | 51 |
| v1 | 41 / 45 / 41 | — |
| v1 训练 240 步（seed 42） | 41 | — |
| 补题、无训练简介 | 52 / 55 / 55 | — |
| v2 | 54 / 49 / 48 | 55 / 56 / 50 |
| v2 Q4_K_M（seed 42） | 52 | 55 |
| DeepSeek Flash | 49 | 55 |
| DeepSeek V4 Pro | 52 | 55 |

v1 在 25 道应查题中只调用了 6–11 次，对 35 道不应查题全部不调用，主要问题仍是漏检索。v2 带简介为 50–56/60，随机种子间相差 6 题；55/60 的 Wilson 95% 区间约为 81.9%–96.4%，不足以对模型排出稳定名次。Q4 与同 seed 的 BF16 带简介时都为 55/60，无简介时为 52 对 54，不能概括为所有输入量化无损。

证据：[冻结题目](../../data/v2/newrepo_nanochat60/questions_frozen.jsonl) · [本地模型、Q4 逐题结果](../../data/v2/newrepo_nanochat60/results/) · [API 逐题结果](../../data/v2/newrepo_nanochat60/results/) · [运行与哈希记录](../../data/v2/newrepo_nanochat60/run_d2.json)

## 结论

- 本轮采用 4B v2，推理时提供当前仓库简介。三个随机种子 与 nanochat 测试均支持补题改善路由；训练简介的独立收益没有得到当前均值支持。
- 50 题与训练集有 1 道完全重合，87 题已参与迭代，不能作为全新独立测试。nanochat 补充了新仓库证据，但只有一个仓库、60 题，仍不足以证明普遍泛化。
- 本章只评单轮工具路由。量化接入后的回答质量、延迟与费用见[第 05 章](05-量化与系统接入.md)；训练与部署命令见 [AutoDL 操作说明](../../lora/autodl/README.md)。
