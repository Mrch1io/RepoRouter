# 回答质量评测与人工复核

[评估目录](README.md) · [上一章：量化与系统接入](05-量化与系统接入.md)

## 实验设置

- 自动评委按 `correct`、`partially_correct`、`incorrect` 三分类判定，并给出 1–5 分。工具决策、检索命中、最终回答质量分别统计。
- 先用两位评委比较 API 回答，再对 原生与 Q4 两条链路做完整回答评测；人工盲评只覆盖第一轮 90 题中的 21 题。
- 原生链路由 DeepSeek Flash 决定工具调用并回答；Q4 由 4B 量化模型路由、Flash 回答。耗时和费用见[第 05 章](05-量化与系统接入.md)。

## 1. 双评委对照

DeepSeek Flash、DeepSeek V4 Pro 各生成 90 份回答，分别交给 Qwen3.8-Max 和 DeepSeek V4 Pro 评分。这批 API 回答与后面的 Q4 对照属于不同运行。

| 被评模型 | Qwen 判正确 | DeepSeek 判正确 | “正确与否”一致 | 三分类一致 |
|---|---:|---:|---:|---:|
| DeepSeek Flash | 78/90 | 80/90 | 84/90 | 79/90 |
| DeepSeek V4 Pro | 76/90 | 78/90 | 78/90 | 76/90 |

两组共有 18 条“模型 × 题目”记录在正确与否上有分歧，去重后为 14 道题。分歧集中在仓库证据是否充分、通用解释是否完成任务，以及未找到证据时应怎样评分。这里保留的是评委意见，不是人工金标。

按 `sample_id` 查询完整理由：[Flash / Qwen](../../data/v2/judge_e2e_deepseek-flash.jsonl) · [Flash / DeepSeek](../../data/v2/judge_e2e_deepseek-flash__by_deepseek-v4-pro.jsonl) · [Pro / Qwen](../../data/v2/judge_e2e_deepseek-v4-pro.jsonl) · [Pro / DeepSeek](../../data/v2/judge_e2e_deepseek-v4-pro__by_deepseek-v4-pro.jsonl)。

## 2. 完整回答评测

各批次使用 Qwen3.8-Max 评分。22 题是早期诊断；frozen90 使用原索引；clean90 从原索引移除四个考题/答案文件的 15 块，保留其余 72 块的向量、正文和元数据，再各跑 90 题一次。

| 运行批次 | 原生链路自动判正确 | Q4 自动判正确 | 原生 / Q4 平均分 | 人工复核范围 |
|---|---:|---:|---:|---|
| 22 题完整回答试评 | 21/22 | 20/22 | 4.77 / 4.68 | 用于诊断案例 |
| frozen90：原索引 | 83/90 | 79/90 | 4.689 / 4.589 | 抽查 21 题、42 份答案 |
| clean90：排除考题文件 | 81/90 | 81/90 | 4.644 / 4.578 | 未重做人工盲评 |

22 题 Q4 使用第二次完整运行，未混入第一次中断的 12 条。两轮 90 题均完整生成和评分，执行错误、评委错误和输出截断均为 0。frozen90 中，已用于诊断的 22 题为 21/22 对 20/22，其余 68 题为 62/68 对 59/68；这 68 题也不等于从未使用过的新题。

frozen90 的对错配对 McNemar `p=0.34375`；clean90 两边各有 8 道独有正确题，`p=1.0`。clean90 的评分差（Q4−原生链路）为 −0.0667，bootstrap 95% 区间为 [−0.2556, 0.1111]。这些小样本结果未检出明确质量差异，也没有证明等价或无损替代。

原索引中，原生链路的 34 次检索有 27 次、Q4 的 33 次有 21 次取回四个考题文件；clean90 的 64 次检索中，这四个文件及当前题目原文的命中均为 0。其它评测实现仍可检索，不能把“干净索引”理解为删除了全部评测源码。[索引派生核验](../../data/v2/clean90/index_derivation.json) · [检索审计](../../data/v2/clean90/retrieval_audit.json)

## 3. 人工盲评

针对 frozen90，在结果生成前固定 seed `20261024` 和 10 道随机题，再加入两条链路三分类不同的全部 11 道题，两组无重合。共 21 题、42 份答案，在隐藏链路名、自动评分和入选原因后复核。

| 抽样组 | 原生：正确 / 部分正确 / 错误 | Q4：正确 / 部分正确 / 错误 |
|---|---:|---:|
| 随机 10 题 | 9 / 1 / 0 | 9 / 1 / 0 |
| 定向分歧 11 题 | 2 / 7 / 2 | 2 / 4 / 5 |

漏判按“人工判非完全正确、自动却判正确 / 人工判非完全正确”计数，其中非完全正确包含部分正确和错误。

- 随机组两边都漏判了 p38，均为 1/1；分母只有一例，不能称为总体漏判率 100%。两边人工正确率 9/10 的 Wilson 95% 区间均为 [59.6%, 98.2%]。
- 分歧组 原生链路漏判 5/9，Q4 漏判 2/9；Q4 的 p07 另有一次反向误判：自动判部分正确，人工判正确。
- 分歧组刻意集中难题，应与随机组分开统计。其余 69 题未人工评阅，不能拼成全量人工准确率；原自动成绩保留不改。
- 每份答案仅留存一条人工标签，运行记录未注明评审人数，也没有多人一致性证据或逐题人工理由。第一轮的人工标签不能套用到 clean90 的新回答。

证据：[预注册抽样规则](../../data/v2/frozen90/review_plan.json) · [原始盲审标签](../../data/v2/frozen90/comparison.review.jsonl) · [人工复核汇总](../../data/v2/frozen90/human_review_summary.json)。预注册文件保留当时“尚未进行”的状态，完成状态以复核汇总为准。

## 4. 典型错误

以下案例来自 22 题完整回答试评，不与两轮 90 题的分数混用。

| 题号 | 问题与证据 | 发现的问题 |
|---|---|---|
| p04 | 问 `search_codebase` 的返回结构；Q4 路由为 `no_tool`，Flash 却用文字声称要调用工具，最终未完成回答 | 共享提示要求调用工具，回答接口却不提供工具清单。评委虽给 3 分、部分正确，仍把证据使用标为合适，未区分“没查”和“查了没找到” |
| p24 | 两边把返回值写成裸列表；旧注释确实这样写，但实际工具结果是含 `results` 的 JSON 对象 | 注释与实际返回冲突，模型未核对，评委也漏核验；Q4 仍获 4 分、正确 |
| m04 | 原生链路定义 A 为 d×r、B 为 r×d，却写 W＋BA | BA 为 r×r，无法加到 d×d 的权重上；评委给了 5 分。Q4 未写这组公式 |

原始记录：[试评回答与评分](../../data/v2/pilot_full_answers/)。p04 的漏查也持续出现在三次早期 90 题和 frozen/clean 两轮中；这不能单独归因于量化，尚无该题未量化与 Q4 的受控对照。

## 结论与后续工作

1. 自动评分能帮助筛选问题，但会漏看任务未完成、证据冲突和公式错误。现有人工复核只验证了局部案例，仍需扩大随机样本并增加独立评审者。
2. clean90 排除了已知考题文件污染，两条链路自动判正确均为 81/90；每条链路只运行一次，未重做盲评。后续应重复端到端实验，并在新仓库上补回答质量评测。
3. 当前源码已修正返回值注释，也给 Q4 回答阶段换了独立系统提示并记录 `answer_tool_call_text`；这些改动尚未做新一轮端到端复测。提示词可以避免假装调用工具，漏查仍需改进路由。
4. 更多随机种子 和 nanochat 新仓库的独立路由评测已完成，见[路由报告](03-路由微调.md)；它们不代替完整 Agent 的回答评测。90 题的费用只统计回答侧 DeepSeek API，未计嵌入、评委及 GPU 成本。

## 工程边界

| 项目 | 当前状态与触发条件 |
|---|---|
| 工具参数 | 当前 `_run_tool` 已检查工具名类型及 `check_tool_args`；旧报告中列表工具名引起 `TypeError` 的问题不能继续写成现状。JSON 可解析仍不等于参数语义正确 |
| 多轮路由 | 历史评测版本只读当前一句；当前实现已传入历史问答，供路由器理解本轮指代。这项改动尚未进行新的端到端评测 |
| 会话与计费并发 | 同一 `session_id` 共享可变 memory，未按会话串行；`USAGE` 是进程全局字典，请求可能相互清零或混入费用 |
| 代码执行隔离 | `run_pytest` 在本机子进程执行生成的代码，临时目录和 30 秒超时未提供文件、网络或环境变量隔离 |

以上是源码可见的边界，不表示它们造成了这批顺序运行的分数差异，也不因 90 题执行错误为 0 就得到验证。历史 [run.json](../../data/v2/frozen90/run.json) 的回归和测量检查只证明对应版本、对应场景通过。
